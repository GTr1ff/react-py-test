## Backend / deployment

The API and the deployment vehicle are one and the same: the Cloudflare
**Python Worker** in [`../python-worker-wsl`](../python-worker-wsl/README.md)
serves `bun run build`'s `dist/` output as Workers static assets and handles
`/api/*` itself — single origin, no CORS, no separate frontend worker.

- **Dev:** `bun run dev` proxies `/api` (and `/docs`) to the Python worker on
  `localhost:8787` — start it with `uv run pywrangler dev` in WSL (see its README).
- **Deploy:** `bun run build` here, then `uv run pywrangler deploy` in
  `../python-worker-wsl` uploads worker and assets together.

## Generated API layer

Each database table gets a generated folder under `src/features/tables/{table.name}/`:

- **`model.ts`** — the typed entity (`Employee`) plus its wire-format interface (`EmployeeJson`) and `fromJson`/`toJson`. Field names are camelCase to match the API's JSON.
- **`repository.ts`** — typed CRUD (`getById`, `getAll`, `search`, `create`, `updateById`, `deleteById`). Each method calls the shared `apiClient`, or the mock store when mocks are enabled.
- **`schema.ts`** — the table's column definitions, used to seed mock data.

These build on shared infrastructure in `src/`:

- **`api/apiClient.ts`** — singleton HTTP client (auth header injection, error normalization to `ApiException`).
- **`config/appConfig.ts`** — reads `VITE_*` env vars (API URL, app title, mocks).
- **`stores/mockDbStore.ts`** — an in-memory mock database (see Mock mode below).

**Configuration.** Set these in `.env` (see `.env.example`):

- `VITE_API_BASE_URL` — backend URL.
- `VITE_USE_MOCKS` — when `true`, repositories read and write an in-memory mock database instead of calling the API. Useful for building UI with no backend running.

**Mock mode.** When `VITE_USE_MOCKS` is `true`, each repository routes to `stores/mockDbStore.ts` instead of the network. The store seeds faker-generated rows on first access per table (from each table's `schema.ts`) and behaves like a real database — `create`, `updateById`, and `deleteById` mutate it, so changes persist across calls within the session. Flip the flag off and the same call sites hit the real API unchanged. Mock data resets on page refresh.

**Using a repository in a component:**

```ts
import { employeesRepository } from "@/features/tables/employees/repository";

const { items } = await employeesRepository.getAll({ page: 1, size: 20 });
```


## Stack

This project is built with:

- **Vite 7** + **React 19** + **TypeScript** (strict)
- **Tailwind CSS v4** (CSS-first; tokens live in `src/index.css`)
- **shadcn/ui** components under `src/components/ui/`

- **Sonner** for notifications, **next-themes** for theming
- **Vitest** + **Testing Library** for unit tests
